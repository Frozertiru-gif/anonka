# Anonka — внешние компоненты и заимствования

Этот файл фиксирует внешние проекты, которые **разрешено использовать как готовые компоненты/доноры кода** внутри Anonka.

Лицензии и источники для всех таких заимствований учитываются централизованно в [`THIRD_PARTY_LICENSES.md`](./THIRD_PARTY_LICENSES.md).

---

## Yuralume / yuralume-core

Upstream: `Yuralume/yuralume-core`

### Решение

**Использовать выборочно, а не переписывать аналогичные механики с нуля.**

Anonka остаётся основным приложением и владельцем Telegram/anon/commerce/runtime архитектуры. Yuralume рассматривается как готовый донор для companion-механик, которые совпадают с нашими продуктовыми требованиями.

### В первую очередь разрешено переиспользовать/адаптировать

- proactive messaging / инициативные сообщения;
- schedule / отложенные действия и возвращение к разговору позже;
- intention gates перед инициативным сообщением;
- relationship-aware поведение;
- persistent/long-term memory primitives, если они подходят к нашей модели conversation;
- механики, помогающие персонажу не быть только реактивным `вопрос → ответ` ботом.

### Что не тащим автоматически

Без отдельного решения не переносить целиком:

- Yuralume UI/frontend;
- LumeGram/social feed;
- WhatsApp/LINE/Discord integrations;
- его общую process/deployment архитектуру;
- PostgreSQL stack только ради совместимости с Yuralume;
- функции, которые дублируют уже рабочие Telegram/MTProto, Gifts, Media Vault, Control Bot или Anonka domain primitives.

### Принцип интеграции

Сначала ищем готовый пригодный модуль/механику Yuralume. Если он подходит — адаптируем к Anonka через наши domain/interfaces вместо написания аналога с нуля.

При каждом прямом переносе или существенной адаптации исходного кода обязательно добавить в `THIRD_PARTY_LICENSES.md`:

- upstream repository;
- upstream commit/tag;
- исходный путь файла/модуля;
- локальный путь в Anonka;
- лицензию;
- краткую пометку, что было изменено.

### Лицензионная граница

Yuralume распространяется как source-available под **Business Source License 1.1 (BUSL-1.1)**. Текущий Anonka используется как личный некоммерческий self-host проект, поэтому использование Yuralume должно оставаться в пределах разрешённого upstream non-commercial/self-host use.

Если назначение Anonka позже изменится на коммерческое production-использование или иной режим, до продолжения использования Yuralume-кода нужно отдельно перепроверить применимую лицензию конкретной версии и при необходимости заменить заимствованный код либо получить соответствующее разрешение/лицензию.
